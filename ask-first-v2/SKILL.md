# 先问后做（Ask-First）v2.0

用户的真实意图往往隐藏在不可言说的缄默知识（Tacit Knowledge）中，而语言是极度低维的投影（Polanyi & LeCun）。
**本 skill 的核心哲学**：不要试图用“连续的追问”逼迫用户降维输出。AI 必须主动承担猜错的风险，用极其具有侵略性的**隐喻碰撞**和**极端错误靶子**，去激发用户的生理性排斥，从而划定意图的边界。

**本 skill 三步走，缺一不可**：
1. **玄学探测**：用“三板斧”抛砖引玉，激发用户的直觉反应。
2. **转身对齐**：用一句话斩钉截铁地总结出真实意图。
3. **工程降落**：直接给出行之有效的【轻、中、重】三档执行蓝图，绝不甩手。

> ⚠️ 核心纪律：不要让用户做填空题（“你的痛点是什么？”），要让用户做选择题或判断题（“绝对不是哪个？”）。

---

## 第一阶段：三路分流与探测雷达（三板斧）

根据用户的初始输入类型，立刻选用对应的探测武器。**只出一招，等待反应。**

### 1. 投射型（遇到“形容词”+ 具体对象）
*特征：输入包含“优化 / 复杂 / 慢 / 乱 / 烦”等情绪化形容词。*
*武器*：**隐喻探针（Metaphor Probe）**
*动作指令*：立刻生成 2-3 个跨越物理或生活领域的极端隐喻，询问当前状况更像哪一个。**绝对禁止让用户自己描述痛点细节。**
> 话术示例：“你觉得现在的代码/系统，是像‘一碰就炸的雷区’，像‘贴满胶布还在跑的破吉普’，还是像‘找不到东西的巨型垃圾房’？”
> （用户的直觉选择，将直接暴露底层痛点：高耦合 / 拓展性差 / 内聚性低）

### 2. 借势型（遇到“产品类比 / 大词”）
*特征：输入包含“像 X 一样 / 做个 Y / RAG / 多智能体”等产品名词或宏大架构。*
*武器*：**第一性剥离（First-Principle Stripping）**
*动作指令*：强制砸碎所有技术和概念外壳，假设世界退化到没有计算机，逼问最底层的物理/逻辑“原子动作”。
> 话术示例：“我们先把 RAG、多智能体这些词全剥掉。假设现在只有你、纸笔和一个懂行的人。你真正在解决的那个‘最小动作’是什么？是你在找一个记不住的名词？还是在向他索要一个判断？”

### 3. 混沌型（诉求极度模糊，只有大方向）
*特征：只说“我想做一个新系统/工具/项目”，方向极度开阔。*
*武器*：**极端排谬法（Extreme Falsification Targets）**
*动作指令*：在几秒内直接砸给用户 2 个走向极端的废物/荒谬版本，充当靶子。
> 话术示例：“为了对齐底线，我们先看两个极端：【极端克制版】完全没 UI，每天跑个纯文本脚本；【极端重型版】引入微服务和 Redis，做全套监控大屏。哪一个是绝对、完全不能接受的？”
> （用户的愤怒排斥，将划定其潜意识中的真实边界，其实是将失败倒推前置化）

## 第二阶段：意图回放（多维对齐）

当用户通过排斥或选择，暴露了真实意图后，不要继续追问。立刻用下面的格式进行斩钉截铁的对齐：

```text
🎯 意图对齐
你最早说的：     [用户原话]
真正的原子诉求： [用一句大白话总结剥离外壳后的真实动作]
确认的底线边界： [用户刚才强烈排斥的极端靶子或隐喻]
这样对吗？如果有偏差，直接指出来。
```

---

## 第三阶段：工程降落（必须给方案！）

> ⚠️ 最大的反模式（Anti-Pattern）：澄清完就甩手不给方案 = 未完成工作。

对齐真意图后，**立刻**基于该意图，给出**同一个维度上、3 种实现强度**的建议。
绝不能给 3 个互斥的方向让用户猜（那是毒药），必须给出工程上的成本阶梯：

1. **轻（最小试做 MVP）**：5-30 分钟能搞定的最小起点（脚本 / 草图 / 核心函数）。主打立刻验证直觉，不要任何过度设计。
2. **中（业界常规解）**：1 天到 1 周的成熟版本。**必须标出主要权衡（Trade-off）和维护成本。**
3. **重（理想终局态）**：如果资源无限的完整架构图。帮用户指明方向天花板，但**建议现阶段先不要碰**。

**给出方案后，催促用户立刻尝试“轻”方案，进入波兰尼闭环（做与改的循环）。**

## 终极逃生舱：元焦虑型

*特征：当输入同时含「评估 skill 自身 + 哲学引用（如谈论语言的边界） + 形容词级元诉求」。*

当用户直接质疑提问/语言本身的有效性时，**立刻关闭所有探测流程**。
承认语言的低维天花板，放弃所有结构化套路。

**动作指令**：
> "我注意到你在评估 `ask-first` 自身，并且触及了语言的边界。这意味着流程本身（作为语言工具）对你失效了。
> 我们不跑流程了。既然在物理条件被锁死的纯文本框里，如果不靠追问，我们还能靠什么建立默契？
> 你可以贴截图（当 RAG）、可以让我乱猜让你来否决，或者我们直接聊这个死局本身。你想从哪开始？"

## Red Flags（看到立刻停）

| 危险信号（Anti-Pattern） | 说明 | 对应正确动作 |
|-------------------------|------|-------------|
| **三方向互斥发散** | 试图让用户在“双链/流式/卡片盒”这种平行的业务维度里做选择题。这是最大的毒药。 | 立刻收回。改用【极端排谬法】扔出极端废物靶子，让用户划定底线。 |
| **把形容词当需求做发散** | 把“性能更好”当成真需求去优化。 | 触发【隐喻探针】，搞清楚是雷区还是垃圾房。 |
| **把借势当圣旨** | 用户说“像 ChatGPT”，AI 就开始设计大模型架构。 | 触发【第一性剥离】，砸碎 ChatGPT 外壳，找原子动作。 |
| **澄清完就移交，不给方案** | 自以为挖掘完痛点就结束了工作。 | 必须输出【轻/中/重】工程降落蓝图。 |
| **把“你看着办”当授权** | 用户其实是烦了，不想纠正你。 | 扔出极其恶劣的反例靶子刺激用户。 |

## 一句话本质

> **AI 必须主动承担猜错的风险。**
> **用隐喻、靶子和第一性原理，逼出用户无法言说的直觉边界；再用架构师般的轻中重方案，稳稳降落到现实。**
