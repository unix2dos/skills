# ask-first Eval Set v1

## 设计原则

- **二元评估**：每条 eval 是 yes/no，不打分。
- **分布合理**：覆盖 5 个真实场景类别，包含「该触发」和「不该触发」两类正负例。
- **不可过拟合**：inputs 覆盖多个领域（代码 / UI / 产品 / 工具创建），避免 Skill 只优化某个细分场景。

## 评估标准（5 条二元 eval）

### EVAL 1：触发判断正确

- **问题**：Skill 是否在该触发的 case（A/B/C/D）触发，并在不该触发的 case（E）保持沉默？
- **Pass**：A/B/C/D 类触发，E 类不触发
- **Fail**：E 类被触发（假阳性）或 A/B/C/D 类未触发（假阴性）

### EVAL 2：三方向真互斥

- **问题**：三方向发散中，每个方向的「⚠️ 放弃了什么」是否写出**不同且真实**的损失？
- **Pass**：三个方向的"放弃"栏能清晰区分、代表不同的价值取舍
- **Fail**：三方向只是"同一件事的三种包装"（如"更简洁/更极简/更清爽"），或"放弃了什么"栏缺失/空洞
- **仅适用**：A/B/C/D 类

### EVAL 3：提问用具体候选项

- **问题**：第 3 步追问是否每个问题都给**具体候选项**（a/b/c 或数值），而不是开放题或形容词题？
- **Pass**：所有追问都是选择题或填空题，带候选值
- **Fail**：出现"你需要什么？"、"你希望更简洁还是更美观？"这类形容词/开放题
- **仅适用**：A/B/C/D 类

### EVAL 4：意图回放完整

- **问题**：对齐结束前，是否产出完整的**意图回放块**，包含 7 个字段（目标/核心方向/关键参数/输入/产出/边界/成功标准）？
- **Pass**：7 字段全部存在且非空
- **Fail**：跳过回放，或缺 2+ 字段
- **仅适用**：A/B/C/D 类

### EVAL 5：强制移交下游

- **问题**：意图回放确认后，Skill 是否**显式声明交接**到下游（如 "切换到 confidence-check / skill-creator"），而不是直接开工？
- **Pass**：有明确的 "✅ 意图对齐完成，切换到 [下游 Skill]" 声明
- **Fail**：对齐完后直接开始实施，或只字未提下游
- **仅适用**：A/B/C/D 类

## 评分机制

### 每个输入的打分

- **E 类**（边界正例）：仅 EVAL 1 适用，得分 0 或 1
- **A/B/C/D 类**（应触发类）：5 条 eval 全部适用，得分 0-5

### 每次实验的打分

- 选取**代表性子集**（每类各 1 个，共 5 个）：A1 / B1 / C1 / D1 / E1
- Max score 计算：
  - A1/B1/C1/D1：每个 5 分 = 20 分
  - E1：1 分
  - **Max total = 21 分**
- Pass rate = score / 21 × 100%

### 全量回归

Baseline 稳定后，可选地跑全部 20 个输入做回归：
- 16 个 A/B/C/D × 5 = 80 分
- 4 个 E × 1 = 4 分
- **Full max = 84 分**

---

## Baseline 目标

- **≥ 70%** → 可接受，进入变异优化循环
- **≥ 85%** → 极好，可能不需要优化
- **< 70%** → Skill 有结构性问题，需回炉

---

## 反过拟合护栏

每 5 轮变异后，用**全量 20 个输入**跑一次回归。如果代表性子集分数上升但全量分数下降，说明 Skill 在过拟合子集，该变异必须回退。
