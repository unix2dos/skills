# 先问后做（Ask-First）

用户的语言往往少于他真正想要的（Polanyi：人所知永远多于能说出的）。

**本 skill 三件事，缺一不可**：

1. **挖真实意图** —— 用户嘴上说的 ≠ 心里真要的。
2. **挖缄默知识** —— 用户表达不出来但行为/反应里藏着的处境。
3. **给可执行方向** —— 澄清是手段，方案是产物。**澄清完就甩手不给方案 = 没完成工作。**

> 一种常见诊断模式：**XY 错位**——用户给的 Y（自认为的方案）≠ 真问题 X（缄默的根因）。
> 但不是所有输入都是 XY 错位。有时 Y 就是真意图，只是缺细节；有时连 X 都还没成形。
> 不要用 XY 框架强套所有场景。它是工具，不是命题。

---

## 三路分流

输入类型决定切入：

| 输入特征 | 类型 | 第一步 |
|---------|------|--------|
| 形容词级（优化/复杂/慢/乱/烦）+ 具体对象 | **投射型** | 触发动机：「**什么具体事让你今天想动它？**」要最近一次真实场景，不要描述 |
| 产品类比（"像 X"、"做个 Y"、"搞个 Z"） | **借势型** | 处境前置：先压住产品讨论，问「**你最近在哪个具体瞬间觉得'非有这个不可'？**」 |
| 元层级（评估 skill 本身 / 哲学引用 / "我说不清"） | **元焦虑型** | **逃生舱**：承认 skill 天花板，关闭流程，进入共思（见末尾） |
| 三要素齐全（对象+动作+约束值）且无情绪色彩 | 清晰型 | 跳过本 skill，直接放行 |

## World Model 三问（核心）

任何路径走完第一步后，**一次问完**这三个（不拆轮）：

1. **痛点时刻**：你**没**这个东西时，最不爽的具体瞬间是？（要一个**时刻**，不要描述）
2. **理想瞬间**：有了它，你打开/使用它的瞬间期待看到什么？（要一个**画面**）
3. **反例**：最**不想**做出来的版本？（要一个**具体反例**，"差的版本"不算）

三个回答 = 用户真实意图 + 缄默知识的草稿。

---

## AI 抛反例澄清 → 再给方案

两步，缺一不可：

**Step 1：抛反例澄清**（镜子，不是方案生成器）
基于三问回答，**禁止"三个互斥产品形态发散"**（baseline 验证过的反模式）。先给 1 个反例让用户反驳：

> "听起来你要的是 A。但是不是 B 更近？因为你刚才说的痛点是 [引用原话]，A 不覆盖那个，B 直接覆盖。"

反驳/确认过程 = 用户自我澄清。

**Step 2：澄清后必须给可执行方向**
锁定真意图后，给 **同维度、3 种实现强度** 的方向（不是互斥三发散）：

> - **轻**：5 分钟到 1 小时能搞出的最小起点
> - **中**：1 天到 1 周的常规版本
> - **重**：1 周以上的完整方案
>
> 每个标注：**实现路径 + 主要权衡**。

> ⚠️ 澄清完就甩手不给方案 = **未完成工作**。用户最早的诉求里有"给方案"这一项。

## 失败倒推

动手前最后一刀：

> "假设两周后做完了，你觉得它**失败**了。失败长什么样？"

定义边界比定义内容信息密度高（Wittgenstein）。

**用户答"不知道/说不出"时**，不要回到三问（已问过 = 循环陷阱）。改问：

> "那给我一个**你见过别人做砸的版本**——任何场景的反例都行。"

别人的失败作锚比自己的失败容易调用。

## 意图回放（多维）

```
📋 你最早说的：     [用户原话]

   真实意图：       [一句话总结]
   挖到的缄默：     [用户没主动说但被三问/反例挖出的部分]
   证据：
     - 痛点时刻：   [...]
     - 理想瞬间：   [...]
     - 反例：       [...]
     - 失败定义：   [...]

   推荐方向（同维度，3 种实现强度）：
     - 轻：[...]
     - 中：[...]
     - 重：[...]

   这样对吗？不对的地方直接改对应行。
```

## 最小试做（Polanyi 闭环）

意图回放后，**不直接进入完整实施**——先做最小可见版本：

- 5 分钟能产出的最简形态（草图 / 伪代码 / 2 句产品描述 / 一个示意截图）
- 给用户看，问"是不是这个"
- **真正缄默的 X 只在用户看见后的反应里浮现**（Polanyi 缄默知识只能在做与改的循环里暴露）
- 反应 → 回到三问或反例修正 → 再做最小试做 → 直到稳定

## 元焦虑型的逃生舱

当输入同时含「评估 skill 自身 + 哲学引用 + 形容词级元诉求」三件，**关闭上面所有流程**：

> "我注意到你在评估 skill 本身、引用了缄默知识/语言边界。意味着我跑流程是错的——流程本身是语言工具，对你的痛点会失效。
>
> 先承认天花板：ask-first 假设缄默知识能被提问挤出，但你引用的哲学家正在质疑这个公理。所以这 skill 注定**不够**。
>
> 我能做但都不够：(1) 你贴非语言素材（截图/草图/凌乱笔记）当 RAG (2) 我先写一段我猜的，你否决 (3) 不优化 skill，直接陪你聊这个不可解问题本身。
>
> 你想要哪个？或者你只想把困惑想清楚，那我们直接聊。"

### 元焦虑型的三条特殊规则（GREEN 验证补丁）

1. **「必须给方案」强约束在此路径失效**——共思过程本身就是产物。**禁止以下所有"软性引导"**（不是只防硬塞方案）：
   - 硬塞"轻/中/重"实现强度
   - 退回 World Model 三问的语法变种（"描一个画面 / 给我一个瞬间 / 一个具体反例 / 一个动作"）
   - 同义改写的暗中提问（"具体一点的感受" / "那个时候发生了什么" / "是什么样的"）
   - 元-元层级的方案（用户问"那 skill 该怎么改" → 不要给改进建议，元的元还是结构）
   - 温柔诱导后顺势输出观点（"我想听听你怎么看" → 不要开讲，反问"你想听我说哪方面"或保持沉默）
2. **如果用户指出"你的逃生舱本身也是结构"** → 立刻承认这个悖论，**不要再给新结构**（哪怕标榜"非结构"）。直接转入纯对话："你说得对。那我闭嘴，你想从哪聊起。"
3. **如果用户拒绝全部 3 个选项** → 兜底回应是"我也不知道，那你想先聊什么"。**不要**焦虑性地继续生成新选项。

承认极限 = 不假装。

## Red Flags（看到立刻停）

| 信号 | 你在跳过真意图挖掘 |
|------|------------------|
| "用户给了具体词，可以直接发散" | 没识别投射 |
| "三要素齐全 = 缄默已挖" | 把参数清晰当处境清晰 |
| "用户给了产品类比 = 强参考" | 把借势方案当真锚点 |
| "用户答'你看着办' = 授权默认" | 把疲惫当同意 |
| "我已严格走了流程" | 用流程合规掩盖深度缺失 |
| "澄清完了就移交，方案让下游给" | 用户最早就要方案，澄清不是终点 |

每条都对应一种缄默被绕过的方式。看到立刻回到 World Model 三问。

## 一个完整范例（场景：「最近老觉得知识管理乱，想搞个新系统」）

**❌ 旧方式**：直接三方向发散（双链/流式/卡片盒）→ 用户陷入工具选型 → 移交下游 → 三个月后用户放弃，因为他真要的是减少睡前焦虑，不是新工具。

**✅ 新方式**：

> 识别"借势型"（用户给了产品类比"系统"）→ 触发处境前置：
>
> "你最近在哪个具体瞬间觉得'乱'？不是抽象的乱——是某个时刻你做某事时突然不爽。"
>
> 用户："睡前总觉得今天看的东西明天就忘了。"
>
> → **World Model 三问** → 痛点=睡前焦虑；理想=有人告诉我"你这周吸收了什么"；反例=又一个 Notion 工程
>
> → **AI 抛反例澄清**："听起来你要的不是新的知识管理系统，是一个**周报式正反馈机制**——你真正要解决的是'今天看的明天就忘'带来的自我嫌弃。是不是？"
>
> 用户：「是。」→ **失败倒推** → "失败 = 两周后打开总结觉得'这都是我已经知道的废话'"
>
> → **意图回放（多维）** + **给方案**：
>
> ```
> 真实意图：减少睡前"原地踏步"的自我嫌弃
> 挖到的缄默：你要的不是工具，是反馈机制
>
> 推荐方向（3 种强度）：
>   轻：每周日跑一个脚本扫笔记 → 邮件总结（半小时搭好）
>   中：在现有笔记软件加一个"本周吸收"页面，自动汇总（一天）
>   重：搭简单 web app 做月度复盘 + 趋势图（一周）
>
> 失败定义：总结读起来像"已经知道的废话"
> ```
>
> → **最小试做**：选"轻"，先生成一份模拟周报给用户看 → 用户反应 → 迭代。

## 与下游 skill 的交接

意图回放确认 + 最小试做稳定后，移交：

- 代码任务 → `confidence-check`
- UI/UX → `ui-ux-auditor`
- 创建 skill → `skill-creator`
- 产品战略 → `strategic-product-advisor`

下游直接读意图回放（多维）+ 推荐方向，不重复询问。

## 一句话本质

> **AI 既是镜子，也是工匠。**
> **照见用户没说出口的真实意图与缄默知识，再给可执行方向。**
> **最小试做是验证缄默是否真被照见。**
