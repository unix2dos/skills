# Case：产品类比 + 第一性剥离

## 用户初始输入

> “我想做一个像 Linear 的 issue tracker，但核心是团队能少开会、少同步。”

## 真实判断

“像 Linear”是借来的外壳，不是真需求。真线索在后半句：少开会、少同步。

## 错误走法

```text
AI: 我们可以做看板、issue 列表、roadmap 三个方向，你想先做哪个？
```

这把 Linear 的产品形态当成了锚点，容易把需求带偏到工具克隆。

## 正确走法

```text
AI: 先把 Linear 这个外壳拿掉。假设没有软件，只有团队、纸笔和一个白板。你真正想减少的同步动作是什么？
A. 大家不知道谁在做什么
B. 不知道一个任务卡在哪
C. 决策散在聊天里没人认领
D. 进展需要人肉汇报

哪个最接近？
```

用户选出原子动作后，再决定轻 / 中 / 重方案。

## Takeaway

产品类比是借势，不是需求。先找**原子动作**，再谈产品形态。
