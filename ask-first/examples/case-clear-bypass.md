# Case：清晰任务直接放行

## 用户初始输入

> “这个保存按钮 bug 烦死我了：点两次会发两个 POST，后端已经有幂等键。只改前端点击防抖，不要碰 API。”

## 真实判断

这不是投射型。虽然有“烦死我了”这种情绪词，但用户已经给了：

- 对象：保存按钮
- 问题：双击发两个 POST
- 约束：后端已有幂等键，只改前端点击防抖
- 禁区：不要碰 API

这类任务要直接执行，不要启动 ask-first。

## 错误走法

```text
AI: 你说“烦死了”，这个问题更像雷区、旧车，还是仓库？
用户: 不是，我已经说了只改防抖。
```

这是把情绪词误当触发条件，制造无意义摩擦。

## 正确走法

```text
AI: 明白。我会只在前端保存按钮加防重复提交，保持 API 不变；验证点是双击只发一次 POST。
```

然后直接读代码、改代码、跑相关测试。

## Takeaway

**情绪不是触发条件。**

如果对象、动作、约束、验收都清楚，直接做。Ask-first 用来处理意图不清，不用来拦截所有带情绪的任务。
