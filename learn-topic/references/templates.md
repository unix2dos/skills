# learn-topic 详细模板

每步的"具体怎么写"。SKILL.md 给骨架，本文给落地模板。

---

## 第 1 步：Hook + 终点告知（120-300 字）

### 模板

```markdown
## 1. Hook + 终点

[第 1 句：命名主角 + 抛痛点，≤40 字]
[第 2-3 句（可选）：桥接，把痛点引到终点，每句 ≤40 字]

读完 [X] 分钟，你将能：[具体可验证的 Apply 动作，≤60 字]
```

### 例（限流主题）

```
小张做电商后台。618 那晚秒杀一开，3 秒后服务器全挂了。

这种"突发流量打挂后端"的场景，标准答案就是限流。但算法有 4 种、阈值怎么定也是学问——选错一个就跟小张一样。

读完 7 分钟，你将能：面对一个新接口，从 3 种限流算法中选对一个，并知道阈值该设多少。
```

### 反例

❌ "你有没有遇到过秒杀被打挂？"——无主角问句
❌ "限流是一种保护后端的技术。"——XX 是一种...
❌ "读完你将理解限流。"——"理解"不是动作

## 第 2 步：演示 I-do（400-700 字）

### 2.1 立单一类比

类比来源按主题类型分流：

| 主题类型 | 类比来源 | 示例 |
|---|---|---|
| 强技术（协议/算法/架构） | 程序员熟悉概念（队列/缓存/线程池/管道/事务） | "Kafka 像超大号消息队列加持久化" |
| 抽象概念（哲学/心理学） | 幼儿园式（积木/食物/玩具/液体） | "认知失调像两块拼不上的积木硬塞同一盒" |
| 通用主题（业务/方法论） | 日常生活（排队/餐厅/收费站/砍价） | "OAuth 像酒店前台给的房卡" |

**铁律**：第 3-5 步必须复用 ≥1 次，**禁换比喻**。

### 2.2 类比 escape hatch（撑不动时的降级路径）

某些主题无合适类比能撑 5 步：

- 纯语法 / 语义（async/await、闭包）
- 递归类（递归、Y combinator、CPS）
- 纯数学（贝叶斯、傅里叶）
- 极抽象元概念（"类型"本身、"指针"本身）

**降级路径**：

1. 用最小代码作"心智锚点"代替类比

```
❌ "async/await 就像点外卖再做别的事"
   → 类比掩盖痛点：函数返回 vs 阻塞

✅ 直接用 3 行代码：
   const data = await fetch(url)  // 这一行做了 3 件事：
   // 1. 发起请求  2. 函数挂起  3. 数据回来后继续
```

2. 第 2 步开头声明 escape："此概念难以用类比解释，原因是 X，所以下面用最小代码作锚点"
3. 第 3-5 步复用的不是类比，而是**那段最小代码**

### 2.3 ⚡ v4 新增：30 秒 PF 预测题

类比之后、worked example 之前：

```markdown
> 💭 **先猜一下**：[问题，≤40 字]
> (a) 选项A  (b) 选项B  (c) 选项C  (d) 选项D
>
> 你的猜测：______（先在心里选一个，再往下读）
```

**目的**：激活先验知识，让接下来的演示从"被动接收"变"验证猜测"。猜错也好——认知冲突反而让记忆更牢（Bjork 的 desirable difficulty）。

### 2.4 完整 worked example

#### 选取标准（4 条全部满足才能用）

1. **典型性**：覆盖该主题"主线痛点"，不是 edge case
   - ✅ 学限流 → "秒杀接口被打挂"
   - ❌ 学限流 → "全球 CDN 智能限流"

2. **决策密度**：含 3-5 个能讲"为什么这步选 X 不选 Y"的决策点
   - ✅ "装限流"→ 选算法/定阈值/选拒绝码/放在哪一层（4 个）
   - ❌ "调用 API"→ 只有"调"一个动作

3. **可压缩到 5 步内 + 700 字内**
   - ✅ "Kafka 生产者发消息"
   - ❌ "搭建 Kafka 集群"

4. **真实性（authenticity，4C/ID 借来）**：模拟真实职业 / 生活实践
   - ✅ "小张做电商后台 618 秒杀挂了"（真职业 + 真公司类型 + 真事件）
   - ❌ "假设有一个 API 服务..."
   - 判断：你能想象一个真人在某真公司/真项目里遇到这个吗？

**反例自检**：写完模板后回看，如果某步没"为什么这么选"可写 → example 缺决策密度，**重选**。

#### 写法模板

```markdown
**步骤 1**：[决策动作，≤25 字]
- 为什么这么选：[原理，≤40 字]
- 类比映射：[复用 2.1 类比，≤25 字]

**步骤 2**：[...]
- 为什么：[...]
- 类比映射：[...]

**步骤 3**：[...]

**最后效果**：[一句话总结，≤40 字]
```

通常 3-5 步刚好。<3 步说明 example 选小了，>5 步说明选大了。

### 2.5 时序型主题嵌图（条件触发）

如果主题是多角色时序（OAuth/TCP 握手/Kafka 生产消费），mermaid `sequenceDiagram` 在此处嵌入。否则跳过。

## 第 3 步：拆解（300-600 字）

### 模板

```markdown
回看 [主角] 的 [N] 步，背后是 [3-4] 条规则：

**规则 1**：[抽象表达，≤25 字]
- 来自步骤 X：[一句回扣，≤40 字]
- 边界：[何时不适用，≤40 字]

**规则 2**：[...]

**规则 3**：[...]
```

### 硬规则

- **严格反向**：所有抽象**必须从第 2 步演示反推**，**禁引入新案例**
- 每条规则**必须有"边界"**——什么时候不适用
- 类比至少复用 1 次

### 易混对比（条件触发）

否定通过制：能想出**真实场景中"有人因为分不清 A 和 B 而踩过坑"**才写。否则跳过。

格式硬规则：表格前 1 行标题 `**易混点**：A vs B`，禁散文导言。

## 第 4 步：半练 We-do（300-500 字）

### 模板

```markdown
### 半练：[主角] 的下一个场景

[场景描述，复用主角，≤80 字]

**问题**：[具体可回答，≤30 字]

💡 先想 30 秒，再继续往下读。

---

**答案**：[简短直接，≤30 字]

- [理由 1]
- [理由 2]
- **经验法则**：[可迁移的判断规则，≤40 字]
```

### 硬规则

- **问题与答案必须视觉分隔三件套**：`💡 先想 30 秒` + `---` 分隔线 + `**答案**` 标题（缺一不可）
- **必须含"经验法则"句**——这是迁移到独挑的桥梁
- **复用主角**，不准切到新主角
- **类比关键词必须显式出现 ≥1 次**——隐含/延伸不算（grep 不到 = 失败）

## 第 5 步：独挑 You-do + 自检（300-500 字）

### 模板

```markdown
### 独挑：你的场景

[场景描述，必须切换到"你"，必须是主体未涉及的新场景，≤100 字]

**问题 1（闭合，有标准答案）**：[问题，≤30 字]

**问题 2（开放，给思考方向）**：[问题，≤30 字]

💡 先想 1-2 分钟。

---

**问题 1 参考答案**：[标答 + 1 句解释]

**问题 2 思考方向**：

- [维度 1，≤30 字]
- [维度 2]
- [维度 3]

不必有唯一答案，关键是看你能不能想到这几个维度。
```

### 硬规则

- **必须切换主角到"你"**
- **必须 1 闭合 + 1 开放**（同种 = 失败）
- 视觉分隔三件套同第 4 步：`💡 先想 1-2 分钟` + `---` + `**问题 N 参考答案**` 标题
- 开放题给"思考方向"而不是"标准答案"
- **类比关键词必须在答案区显式出现 ≥1 次**——切换到"你 + 新场景"时注意力容易偏移到新内容，**类比最容易在这里漏**

### ⚠️ 易翻车提醒

第 5 步是类比纪律的"高危区"：
- 主角换了（你）+ 场景换了（新领域），写作者注意力放在解新题
- 但类比 1.2 立的那个比喻**仍要出现**——读者读到第 5 步时，正是单一类比"贯穿全文"价值最高的时刻
- **写完 Step 5 答案立即 grep 类比关键词**，没有就重写

## 末尾附录区：完整规则

### 附录 A：全景图（mermaid）

**触发条件（任一满足）**：
1. 多角色时序 → `sequenceDiagram`
2. 状态机 → `stateDiagram-v2`
3. 复杂网状关系（节点 ≥5 且关系 ≥7 且表格无法表达）→ `flowchart` / `block-beta`
4. 历史 / 演进脉络（≥4 个时间节点 + 关键转折）→ `timeline`

**反例（不出图）**：
- 单一概念
- 几个并列概念（4 种限流 → 表格够了）
- ≤4 节点的简单结构

**位置**：
- 时序型 → 已在第 2 步嵌入，附录 A 不重复
- 结构型/演进型 → 附录 A
- 不触发 → 完全不写"附录 A"标题

调用 `@mermaid-generator`。图必须 ≤15 节点。

### 附录 B：核心术语速查表

**触发**：主题含 ≥5 新术语。
**格式**：4 列（术语/人话解释/类比/常见误解），每格 ≤15-20 字。

### 附录 C：5W2H 速查

**触发**：复合方法论（如 OAuth 流、限流体系）。
**格式**：6 行（What/Why/Who/When/Where/How/How much）。

不需要的附录**完全不写标题**。
