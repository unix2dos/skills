# learn-map v3 · 5 步认知爬升

## 核心理念

**v3 与 v1/v2 的根本区别**：v1/v2 是"信息陈列式"（每段都让读者接收信息），v3 是"**认知任务渐进式**"（每步逼读者干不同的认知动作）。

读完 7 分钟，读者**能在新场景应用**该知识——这是 Bloom Apply 层级，不是 Understand 层级。

### 三大学习科学锚点
1. **CLT 认知负荷理论**：新手必须先看 worked example（演示），再做 completion task（半练），最后独立练。颠倒就死。
2. **UbD 倒推设计**：开头明示终点（"读完你将能 X"），不到末尾才出检验题。
3. **Make It Stick 检索练习**：必须有思考间隙才有 retrieval。`<details>` 折叠是单文件能做到的最大检索强度。

---

## ⚠️ 自检归属

文档所有"自检"段落都是**作者写作时的内部检查动作**，不是输出格式的一部分。
- ❌ 禁止把"自检通过"作为段落写进最终输出
- ✅ 自检发现违规 → 必须修 → 重新自检 → 全过才输出

---

## 受众定位（写作前先校准）

默认读者是**跨领域成熟读者**：在自己领域是高手，但对该主题陌生。

- ✅ 类比可以从读者**已熟悉的另一领域**借（如对程序员讲心理学就用"线程竞争"比喻"认知冲突"）
- ✅ 每段允许 ≤1 个未在该主题内定义过的术语
- ❌ 不要假设读者懂该主题的任何专有词汇
- ❌ 不要从"什么是 HTTP"级别的前置知识开始

如果读者明显是真新手或同领域中级，调整类比密度即可，骨架不变。

## 输出结构：5 步认知爬升（严格按顺序）

```
1. Hook + 终点告知 (150-300 字)
2. 演示 I-do          (400-700 字)
3. 拆解               (300-600 字)
4. 半练 We-do         (300-500 字)
5. 独挑 You-do + 自检 (300-500 字)

主体总量：1500-2600 字
附录区  ：0-500 字（条件触发）
```

---

### 第 1 步：Hook + 终点告知（120-300 字）

#### 1.1 主角痛点 + 桥接（1-3 句，每句 ≤40 字）

第 1 句必须命名主角 + 抛痛点。后续 1-2 句可作"桥接"——把读者从痛点引到终点承诺。



**必须命名一个具体主角**——给名字、给场景、给具体痛点。不写抽象问句。

✅ 示例：
> 小张做电商后台。618 那晚秒杀一开，3 秒后服务器全挂了。

❌ 失败：
> "你有没有遇到过秒杀被打挂的场景？"——没主角，只是问句。

❌ 失败（XX 是一种...）：
> "限流是一种保护后端服务的技术。"

#### 1.2 终点承诺（必需，1 句话，≤60 字）

借自 UbD：明示读完后的 Apply 能力，必须**具体可验证**。

✅ 示例：
> 读完 7 分钟，你将能：面对一个新接口，在 3 种限流算法中选对一个，并知道阈值怎么定。

❌ 失败：
> "读完你将理解限流。"——理解 ≠ Apply，无法验证。

#### ⚠️ 第 1 步硬规则
- 整段共 120-300 字
- 第 1 句必须命名具体主角（给名字 + 场景）
- 终点必须是**动作描述**（"能选对、能识别、能设计"），不是"能理解、能掌握"
- 句长档位 B（≤40 字）

---

### 第 2 步：演示 I-do（400-700 字）

#### 2.1 立单一类比（必需，全文复用）

按主题类型分流：

| 主题类型 | 类比来源 |
|---|---|
| 强技术（协议/算法/架构） | 程序员熟悉概念（队列/缓存/线程池/管道） |
| 抽象概念（哲学/心理学） | 幼儿园式（积木/食物/玩具/液体） |
| 通用主题（业务/方法论） | 日常生活（排队/餐厅/收费站） |

**铁律**：这个类比一旦立了，第 3-5 步必须复用 ≥1 次，**禁换比喻**。撑不到第 5 步的比喻，重选。

#### 2.1.5 类比 escape hatch（撑不动时的降级路径）

某些主题没有合适的单一类比能撑 5 步——常见场景：

- **纯语法 / 语义**（`async/await`、`for...of` 循环、闭包）
- **递归类概念**（递归、Y combinator、CPS 变换）
- **纯数学公式**（贝叶斯定理、最大似然估计、傅里叶变换）
- **极抽象的元概念**（"类型"本身、"指针"本身、"语义"本身）

硬套类比反而误导。**降级路径**：

1. **用最小代码 / 最小例子代替类比**——伪代码或一行真实代码作"心智锚点"

   ```
   ❌ 失败："async/await 就像点外卖再做别的事——外卖到了再回来吃"
       → 类比掩盖了真正痛点：函数返回 vs 阻塞

   ✅ 通过：直接用 3 行代码当锚点
       const data = await fetch(url)  // 这一行做了 3 件事：
       // 1. 发起请求  2. 函数挂起  3. 数据回来后继续
   ```

2. **声明 escape**：在第 2 步开头直接写"此概念难以用类比解释，原因是 X，所以下面用最小代码作锚点"

3. **escape 后的复用规则**：第 3-5 步复用的不是类比，而是**那段最小代码**——反复回到它，逐步深化

**判断**：硬挤一个不贴的类比 vs 直接用最小代码 → 后者总是更诚实。**escape 不是失败，是诚实**。

#### 2.2 完整 worked example（必需，主体）

**先选好 example，再下笔写。** Example 选错，整个第 2 步白写。

##### 选取标准（3 条全部满足才能用）

1. **典型性**：覆盖该主题的"主线痛点"，不是 edge case
   - ✅ 学限流 → 选"秒杀接口被打挂"（典型场景）
   - ❌ 学限流 → 选"全球 CDN 智能限流"（边角场景，学不到核心）

2. **决策密度**：含 3-5 个能讲"为什么这步选 X 不选 Y"的决策点
   - ✅ "装限流" → 选算法 / 定阈值 / 选拒绝码 / 放在哪一层（4 个决策）
   - ❌ "调用 API" → 只有"调"一个动作，无决策可讲

3. **可压缩到 5 步内 + 700 字内**
   - ✅ "Kafka 生产者发消息" → 4-5 步可讲完
   - ❌ "搭建 Kafka 集群" → 30+ 步，根本塞不下

**反例自检**：写完模板后回看，如果某步没有"为什么这么选"可写，说明 example 没决策密度，**重选**。

##### 写法

让主角面对你选好的 example，**逐步求解**。

每个决策点都解释"为什么这步选 X 不选 Y"——这是 CLT 验证的关键。

模板：
```
小张面对秒杀场景，他这样一步步装限流：

步骤 1：[决策动作，≤25 字]
   → 为什么这么选：[原理，≤40 字]
   → 类比映射：[复用 2.1 类比，≤25 字]

步骤 2：[...]
   → 为什么：[...]

步骤 3：[...]

最后效果：[一句话总结，≤40 字]
```

通常 3-5 步刚好。少于 3 步说明 example 选小了，多于 5 步说明 example 选大了。

#### 2.3 时序型主题在此处嵌图（条件触发）

如果主题是**多角色时序**（OAuth 流、TCP 握手、Kafka 生产消费），mermaid `sequenceDiagram` 在此处嵌入——图本身就是 worked example 的视觉表示。

否则跳过——大多数主题在第 2 步**不需要图**。

#### ⚠️ 第 2 步硬规则
- 演示必须有具体主角名 + 具体场景
- 每个步骤必须解释决策理由
- 字数 400-700：超 700 说明 example 选大了，砍场景
- 类比在第 2 步至少出现 2 次

---

### 第 3 步：拆解（300-600 字）

#### 3.1 反向抽规则（主体）

**严格反向**：所有抽象**必须从第 2 步演示反推**，**不准引入新案例**。

模板：
```
回看小张的 3 步，背后是 3 条规则：

规则 1：[抽象表达，≤25 字]
   ← 来自小张的步骤 X：[一句回扣，≤40 字]
   边界：[何时不适用，≤40 字]

规则 2：[...]

规则 3：[...]
```

通常 2-4 条规则。规则必须有"边界"——什么时候不适用，否则就是空话。

#### 3.2 易混对比（条件触发，否定通过制）

只有当你能想出**真实场景中"有人因为分不清 A 和 B 而踩过坑"**的具体例子才写。否则跳过。

格式硬规则：表格前最多 1 行对比标题（≤15 字），格式 `**易混点**：A vs B`，禁散文导言。

| 维度 | A | B |
|---|---|---|
| 定义 | ... | ... |

#### ⚠️ 第 3 步硬规则
- 禁引入新案例（要新案例就违反"反向"原则）
- 每条规则必须有"边界"
- 类比至少复用 1 次

---

### 第 4 步：半练 We-do（300-500 字）

#### 4.1 复用主角的新场景

**主角不变，场景换**——降低认知负荷，让读者注意力集中在**思考决策**而不是**理解新场景**。

#### 4.2 提问 + 折叠答案（必需）

**强制 `<details>` 折叠**——这是 retrieval 真正发生的瞬间。

模板：
```markdown
### 半练：小张的下一个场景

[主角面对一个新场景，≤80 字描述]

**问题**：[具体可回答的问题，≤30 字]

> 💡 先想 30 秒再展开。

<details>
<summary>查看答案</summary>

**[答案]**。
- [理由 1]
- [理由 2]
- 经验法则：[可迁移的判断规则，≤40 字]

</details>
```

#### ⚠️ 第 4 步硬规则
- 必须用 `<details>` 折叠（直接给答案 = 失败）
- 必须有"经验法则"句——这是迁移到独挑的桥梁
- 复用主角，不准切到新主角
- 类比至少复用 1 次

---

### 第 5 步：独挑 You-do + 自检（300-500 字）

#### 5.1 切换到读者本人

**主角换成"你"**——这是迁移测试，验证读者能否把刚学的规则用到全新场景。

#### 5.2 1 闭合 + 1 开放

```markdown
### 独挑：你的场景

[场景描述，≤100 字，必须是主体未涉及的新场景]

**问题 1（闭合，有标准答案）**：[问题，≤30 字]

**问题 2（开放，给思考方向）**：[问题，≤30 字]

<details>
<summary>问题 1 参考答案</summary>

[标答 + 1 句解释]

</details>

<details>
<summary>问题 2 思考方向</summary>

[3-5 个判断维度，bullet 形式，每条 ≤30 字]
不必有唯一答案，关键是看你能不能想到这几个维度。

</details>
```

#### ⚠️ 第 5 步硬规则
- 必须切换主角到"你"
- 必须 1 闭合 + 1 开放（同种类型 = 失败）
- 都用 `<details>` 折叠
- 开放题给"思考方向"而不是"标准答案"

---

## 末尾附录区（条件触发）

附录是**给"想速查"的人**的，不破坏主流叙事。

**核心原则**：不需要的附录**完全不写**——不留空标题、不写"无"。

### 附录 A：全景图（mermaid）

**触发条件（任一满足）**：
1. 多角色时序（如 OAuth/TCP/Kafka 生产消费）→ `sequenceDiagram`
2. 状态机（如 TCP 状态、订单生命周期）→ `stateDiagram-v2`
3. 复杂网状关系（节点 ≥5 且关系 ≥7，且表格无法表达）→ `flowchart` / `block-beta`
4. 历史/演进脉络（≥4 个时间节点 + 关键转折）→ `timeline`

**反例（不出图）**：
- 单一概念（沉没成本）
- 几个并列概念（4 种限流算法 → 表格已够）
- ≤4 节点的简单结构

**位置**：
- 时序型 → 已在第 2 步嵌入，附录 A 不重复
- 结构型 / 演进型 → 放附录 A
- 不触发 → 完全不写"附录 A"

调用 `@mermaid-generator` 生成图。图必须 ≤15 节点。

### 附录 B：核心术语速查表（≥5 术语时启用）

4 列：术语 / 人话解释 / 类比 / 常见误解。每格 ≤15-20 字。
术语 < 5 → 跳过整段。

### 附录 C：5W2H 速查（复合方法论时启用）

6 行：What/Why/Who/When/Where/How/How much。
单一概念 → 跳过整段。

## 语言风格

| 维度 | ❌ 不要 | ✅ 要 |
|---|---|---|
| 开场 | "XX 是一种..." | 命名主角 + 具体痛点 |
| 终点 | "你将理解 X" | "你将能 X"（动作） |
| 解释 | 直接抛术语 | 类比 → 定义 → 细节 |
| 答案 | 直接给 | `<details>` 折叠 |
| 全景图 | 必出 | 条件触发（默认跳） |
| Emoji | 每段都有 | 仅警告（⚠️❌✅）和提示（💡） |

### 句长档位（沿用 v2）

#### 档位 A：≤25 字（扫读型）
表格内、bullet、checklist、术语解释、规则、4.2 折叠内 bullet。

#### 档位 B：≤40 字（叙事/推理型）
1.1 痛点、1.2 终点、2.2 worked example 解释、3.1 边界、4.2 答案理由、5.2 开放题思考方向。

不存在档位 C——超过 40 必拆。

### 每步强制 ≥1 处轻松元素

防止教科书化。每步至少 1 处：
- **自嘲**："这一步很多人会跳过——主要是因为懒"
- **反问**："你猜小张这次又栽在哪？"
- **具象比喻**：复用类比，"就像那个收费站——又堵了"

## 🔴 提交前自检清单

### 自检 1：脊柱合规（最先查）
```
□ 第 1 步是否在 1 句话内告知"读完你能 [Apply 动作]"？
□ 第 2 步是否有完整 worked example，每个决策点都解释？
□ Worked example 是否过 3 条筛选（典型性 / 决策密度 / 可压缩）？
□ 类比撑不动的主题，是否走 escape hatch（最小代码 + 声明），而非硬挤？
□ 第 3 步是否所有抽象都从第 2 步反推，没引入新案例？
□ 第 4 步是否复用主角 + 用 <details> 折叠 + 含"经验法则"句？
□ 第 5 步是否切换到"你" + 1 闭合 + 1 开放 + 都折叠？
```

### 自检 2：篇幅
```
□ 第 1 步：120-300 字？
□ 第 2 步：400-700 字？
□ 第 3 步：300-600 字？
□ 第 4 步：300-500 字？
□ 第 5 步：300-500 字？
□ 主体总量 ≤ 2600 字？
```

### 自检 3：附录纪律
```
□ 不需要的附录是否完全没出现（不留空标题、不写"无"）？
□ 附录 A 全景图：是否真的过门槛（4 条触发条件之一）？
□ 附录 B 术语：术语数 ≥5？
□ 附录 C 5W2H：是复合方法论而非单一概念？
```

### 自检 4：类比纪律
```
□ 第 2 步立的类比，第 3/4/5 步是否各复用 ≥1 次？
□ 全文是否始终一个比喻，没换过？
```

### 自检 5：句长 + 风格
```
□ grep `——` 和 `（）` 同句出现 → 必拆
□ grep ≥2 个逗号的句子 → 大概率超 40，拆
□ 抽 3 条扫读区逐字数：≤25？
□ 抽 3 条叙事区逐字数：≤40？
□ 每步是否都有 ≥1 处轻松元素？
```

### 自检 6：易翻车点
```
□ 1.1 不是"XX 是一种..."开场？
□ 1.2 终点是动作描述（"能选对/能识别"）而不是"能理解"？
□ 第 4/5 步答案是否真的用 <details> 折叠？没近距离暴露？
□ 第 5 步是否真的切换到"你"，没继续用主角？
□ 文档没有"自检通过"等元注释？
```

### 自检 7：闭环
不通过 = 已修，不是只标记。修完重跑自检 1+5，直到全过才输出。
