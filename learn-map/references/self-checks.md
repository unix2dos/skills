# learn-map v4 Red Flags 详细解析

每个红旗背后的"为什么是错"。SKILL.md 的 Red Flags 表是触发器，本文是当你拿不准时的判断依据。

---

## 🚩 第 1 步终点用"理解/掌握"

**为什么是错**：
"理解 X" 是 Bloom Understand 层级（能解释），"掌握 X" 模糊不清。learn-map v4 的目标是 Bloom **Apply**——能在新场景做事。

**测试**：终点是"能"+ 动作动词（识别/选对/设计/判断），就过；否则就违规。

**修复**：把"理解限流" → "面对一个新接口能选对算法"。

---

## 🚩 第 1 句不命名主角

**为什么是错**：
4C/ID 的 authenticity 原则——抽象问句（"你有没有遇到过..."）激活不了"真人在真公司遇到真事"的具象认知，读者代入感弱。

**测试**：第 1 句必须有具体名字（小张/老李）+ 真实公司类型（电商后台/AI 笔记产品）+ 真实事件（618 秒杀挂了）。

**修复**：换成"小张做电商后台。618 那晚秒杀一开，3 秒后服务器全挂了"模板。

---

## 🚩 第 2 步没有 30 秒 PF 预测题

**为什么是错**：
Productive Failure 研究表明——读者在看演示前先尝试预测，激活先验知识，让后续 worked example 从"被动接收"变"验证猜测"，记忆留存显著上升。即使猜错也好（Bjork 的 desirable difficulty）。

**测试**：类比立完之后、第一个步骤之前，必须有"💭 先猜一下"块。

**修复**：插入"💭 先猜一下：你会用 a/b/c/d？"（4 选 1 最佳，给读者明确选项）。

---

## 🚩 第 2 步某步没"为什么这步选 X 不选 Y"

**为什么是错**：
CLT 的 worked example 价值在"显式呈现决策过程"。只列步骤不解释 = 读者只能模仿，不能迁移。这等于 example 缺**决策密度**——选取标准第 2 条违反。

**测试**：每个步骤后必须有"为什么这么选"的一句话。如果某步写不出，说明 example 选错了。

**修复**：重选 example。比如把"调用 API"换成"装限流"——后者每步都有真决策。

---

## 🚩 第 2 步是"假设有一个..."

**为什么是错**：
违反 4C/ID 的 authenticity。教科书腔调让读者意识到这是"假"场景，认知投入下降。

**测试**：example 描述里必须有具体公司类型 + 真实业务场景，不能是"假设"、"考虑这样"、"想象一个"。

**修复**：把"假设有一个 API 服务需要限流..." → "小张做电商后台，618 秒杀..."

---

## 🚩 第 3 步引入第 2 步没出现过的新案例

**为什么是错**：
第 3 步的价值是"反向抽规则"——读者已对第 2 步演示有上下文，从演示反推规则的认知负荷低。引入新案例 = 读者要建立新场景理解 + 抽规则，认知负荷翻倍。

**测试**：第 3 步的"来自步骤 X"必须真的指向第 2 步的某步。

**修复**：删新案例，强制从第 2 步反推。如果觉得第 2 步演示不够撑起规则，重写第 2 步。

---

## 🚩 第 4/5 步答案没和问题视觉分隔

**为什么是错**：
Make It Stick 的核心证据：**必须有思考间隙才会触发 retrieval**。答案近距离暴露 = 读者眼一扫就过，0 留存——和读普通博客没区别。

**测试**：问题与答案之间必须有"分隔三件套"：
1. `💡 先想 30 秒` 或 `💡 先想 1-2 分钟` 提示
2. `---` 水平分隔线（视觉中断）
3. 显式 `**答案**` 或 `**问题 N 参考答案**` 标题

**修复**：

```markdown
**问题**：你的问题

💡 先想 30 秒，再继续往下读。

---

**答案**：直接回答 + 经验法则
```

注意：v3.1 用 `<details>` 折叠，v4 改用视觉分隔——折叠在某些渲染器（终端/纯文本）失效，分隔三件套通用。

---

## 🚩 第 4 步答案块没"经验法则"句

**为什么是错**：
半练的目的是"半做+给规则"，规则是迁移到第 5 步独挑的桥梁。没规则 = 读者只学会一个具体案例，迁移失败。

**测试**：折叠答案块的最后必须有 "**经验法则**：[可迁移的判断规则]"。

**修复**：在答案块末尾加一行"经验法则"。

---

## 🚩 第 5 步还在用小张/老李

**为什么是错**：
第 5 步是 transfer test——验证读者能把规则从主角场景迁移到自己场景。还用主角 = 没真正测试迁移。

**测试**：第 5 步的"独挑"场景必须以"你"为主语。

**修复**：场景换成"你接手了一家 SaaS 公司..."、"你买了一年健身房卡..."

---

## 🚩 类比中途换了

**为什么是错**：
违反 generation effect——读者每复用一次类比都是一次主动 generation，巩固神经通路。换比喻 = 读者每次都在"建立新映射"，记忆负担加倍。

**测试**：第 2 步立的比喻，第 3-5 步必须出现完全相同的比喻词汇。

**修复**：要么坚持原比喻，要么走 escape hatch（用最小代码代替）。

---

## 🚩 第 4/5 步答案区没显式出现类比关键词

**为什么是错**：
"复用类比"≠"用类比的思想"。Generation effect 要求读者**看到那个具体词汇**，激活神经通路。"长期 secret 换一次性 secret"在思想上延伸了"两段式凭证交换"，但读者大脑里没有触发"两段式"那个 token——记忆通路没激活。

**高危位置**：

- **Step 4**：复用主角但换场景，注意力放在新场景的解法
- **Step 5**：切换到"你"+ 全新场景，类比最容易"消失"

**测试**（写完答案立即跑）：

```bash
# 把第 2 步立的类比关键词列出来，比如 OAuth 是"两段式" "凭证交换"
# 在 Step 4/5 答案区 grep
grep -E "两段式|凭证交换" Step4-5部分
# 至少 1 次匹配 = 通过；0 次 = 失败
```

**修复**：在答案的某句话里**显式写**类比关键词。不是改思想，是改用词——把"动态生成 secret"补成"两段式的第二段从静态换成动态"。

**反例**（OAuth Step 5 第一版）：
> Authorization Code Flow + PKCE。员工是真人，需要交互式登录...SPA 没后端存 secret，必须叠 PKCE。

—— 没出现"两段式"。读者读到这里，第 2 步立的比喻消失了。

**正例**（修复版）：
> Authorization Code Flow + PKCE。员工是真人，要交互式登录——必须走"两段式凭证交换"...SPA 没后端存 secret，必须叠 PKCE 把"长期 secret"换成"一次性 secret"——动态版的两段式。

—— "两段式" 显式出现 3 次，类比通路被激活。

---

## 🚩 出图但没过 4 条触发门槛

**为什么是错**：
v1/v2 的图常常是装饰性的（"4 种算法画成 flowchart"），表格更清晰。开篇懵逼图就是这样产生的。

**测试**：你的图是否真满足 4 条触发条件之一（多角色时序 / 状态机 / ≥5 节点 ≥7 边 / 历史脉络）？

**修复**：删图，改用表格或 bullet 列表。

---

## 🚩 文档里出现"自检通过"等元注释

**为什么是错**：
自检是写作过程的内部动作，不是输出。把"自检通过"写进输出 = 把脚手架留在成品里。读者不该看到检查过程。

**测试**：grep "自检"、"匹配通过"、"已数 X 字"等词。

**修复**：删除所有"自检过程"段落。

---

## 元规则：闭环

不通过 = 已修，不是只标记。修完重跑 Red Flags + 量化自检，全过才输出。

**自检的价值在修完问题，不在发现问题**。
